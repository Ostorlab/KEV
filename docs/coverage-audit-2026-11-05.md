# Prioritized coverage audit — 2026-11-05

This documentation update reconciles 30 prioritized CVEs with pending Asteroid
implementation: **seven remote metadata CVEs in four registered detectors** and
**23 offline owner-inventory CVEs in 21 assessors**. The README updates 18 existing
rows and adds the 12 missing rows at the top of its coverage table.

The seven remote rows remain **⏳ in progress** until Asteroid integration and
release. The other 23 remain **❌ not detected by the automatic agent group**:
they have a separate owner-inventory assessment, not a network detector. None of
these rows is marked ✅ based on unmerged source.

The original prioritized audit compared Asteroid
[`571a9bc8217cd2c9a327d73ef309e3ad70e3784f`](https://github.com/Ostorlab/agent_asteroid/tree/571a9bc8217cd2c9a327d73ef309e3ad70e3784f)
and KEV
[`9caf2d988fed30ef971eb8f86445132912307285`](https://github.com/Ostorlab/KEV/tree/9caf2d988fed30ef971eb8f86445132912307285)
with [CISA KEV](https://github.com/cisagov/kev-data/blob/main/known_exploited_vulnerabilities.json)
catalog version **2026.11.04 (1,768 entries)**. It selected these 30 gaps; it was
not an exhaustive audit of remotely exploitable CVEs or deployed scanner images.
Implementation was subsequently integrated against updated Asteroid main.
Dates below are CVE/CNA publication dates, not CISA addition dates.

## Implementation and runtime conditions

Source links are pinned to Asteroid commit
[`580cf1f3e8c99f944a904f30e8040af75c81974b`](https://github.com/Ostorlab/agent_asteroid/tree/580cf1f3e8c99f944a904f30e8040af75c81974b),
which contains all four implementation batches and their detailed contracts.
The branch's pending review/release status is separate from this immutable source
reference. A later import-order integration change does not alter these policies.

The existing [agent group](../agent_group.yaml) already runs Asteroid default
checks. Once an agent release includes this implementation, supported discovered
targets with accessible qualifying metadata can produce the seven remote
potential-exposure findings. A source commit alone does not establish that the
installed agent image contains them. No templates or scanner configuration are
changed by this documentation update.

Nuclei remains enabled with explicit `template_urls`; `use_default_templates:
false` disables broad defaults, not the Nuclei agent or its configured templates.
An upstream template's existence alone does not establish execution by this group.

Owner-inventory assessments run separately in an Asteroid checkout/environment
containing the implementation:

```sh
python -m agent.utils.inventory docs/examples/cisco-ise-inventory.json
python -m agent.utils.inventory docs/examples/secure-email-inventory.json
python -m agent.utils.inventory docs/examples/salt-inventory.json
```

The [public inventory dispatcher](https://github.com/Ostorlab/agent_asteroid/blob/580cf1f3e8c99f944a904f30e8040af75c81974b/agent/utils/inventory.py)
accepts one record through `assess_records(record)`; its CLI accepts a JSON array
and performs no target I/O. Product dispatch can additionally emit existing CVEs
outside this audit. The 23-CVE count counts identifiers, including the two-ID
RouterOS SSH and TrueConf family assessments.

Remote metadata is evidence of **potential exposure, with exploitability
unconfirmed**. Product/version evidence does not establish feature availability,
access controls, backports or every stage of an exploit chain. Missing, hidden,
ambiguous or unsupported metadata yields no finding, which does not prove safety.

Offline results require trusted owner collection of the same running instance's
product, release, patch and effective configuration evidence. The assessors do
not independently authenticate those assertions, package provenance or hotfix
applicability. Complete examples are synthetic normalized inputs, not vendor API
responses. Repeat collection for each serving/failover node.

`potential_exposure` means the supplied evidence matches an advisory rule.
`not_matched` can mean a CVE-specific software fix, an excluded interval, a
configuration exclusion or a supported mitigation; inspect the reason.
Configuration exclusions and temporary mitigations do not establish fixed
software or rule out prior compromise. `inconclusive` means material evidence
is missing, malformed, contradictory or unsupported. Unknown/future releases
are not presumed fixed. The detailed documents define each policy's exceptions.

No live target or vulnerable/patched lab validation was performed. Offline
fixtures and tests establish implementation behavior, not deployed effectiveness.
